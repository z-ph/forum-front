# Repository Guidelines

## Project Structure & Module Organization
`src/` contains the Vue 3 + TypeScript app. Use `src/pages/` for file-based routes handled by `unplugin-vue-router`; route files follow `*.page.vue`. Put reusable UI in `src/components/`, shared data hooks in `src/hooks/`, API and app setup in `src/core/`, mock or remote service calls in `src/services/`, and shared types in `src/types/`. Static assets belong in `public/` or `src/assets/`. Do not hand-edit `src/typed-router.d.ts`; it is generated by the router plugin.

### File-Based Routing Conventions

| File pattern | Route path | Purpose |
|--------------|------------|---------|
| `index.page.vue` | `/` | Index/home route |
| `about.page.vue` | `/about` | Static route |
| `[id].page.vue` | `/:id` | Dynamic param (required) |
| `[[id]].page.vue` | `/:id?` | Optional param |
| `[...path].page.vue` | `/:path(.*)` | Catch-all (404) |
| `parent.page.vue` + `parent/` folder | Nested layout | Parent wraps children in `<RouterView>` |

**URL nesting without layout**: Use dot notation (`users.profile.page.vue` → `/users/profile`) when URL should nest but UI shouldn't.

**Route groups**: Parentheses like `(forum)/` create shared layout without affecting URL path.

**Type-safe navigation**: Use route name strings for typed params:
```ts
router.push({ name: '/topics/[id]', params: { id: '123' } })
const route = useRoute('/topics/[id]')
route.params.id // typed as string
```

## Build, Test, and Development Commands
Use `pnpm` for local work:

- `pnpm dev` starts the Vite dev server.
- `pnpm build` runs `vue-tsc -b` and then creates a production bundle in `dist/`.
- `pnpm preview` serves the built app locally for verification.
- `pnpm typecheck` runs TypeScript and Vue SFC checks without building.

The pre-commit hook runs `pnpm typecheck`, so keep the tree type-safe before committing.

## Coding Style & Naming Conventions
Follow the existing Vue SFC pattern: `<script setup lang="ts">`, Composition API, and colocated template/style blocks. Prefer single quotes and the semicolon-light style already used across `src/`. Use PascalCase for component files (`ForumHeader.vue`), camelCase for composables and utilities (`useForum.ts`, `apiClient.ts`), and descriptive route names based on the file path. Keep feature-specific styling scoped inside the component unless it is truly global.
Use object-style navigation for all Vue Router calls. Do not pass raw string paths to `router.push` or `router.replace`; always use objects such as `router.push({ path: '/latest' })` or named-route objects when available.

## Testing Guidelines
There is no committed unit test suite yet. Until one is added, treat `pnpm typecheck` and `pnpm build` as required validation for every change. For UI changes, manually verify the affected flows in `pnpm dev`, especially route navigation, query-driven state, and responsive layouts.

## Commit & Pull Request Guidelines
Recent history uses short, focused Chinese subjects such as `添加组件库依赖` and `修改项目名称`. Keep commits small, imperative, and limited to one change. For pull requests, include a brief summary, linked issue or task when available, screenshots for visible UI changes, and note any config or API contract changes such as updates to `openapi.yaml` or `.env.example`.

## Configuration Tips
Environment values live in `.env` and `.env.example`. `VITE_API_URL` drives the Vite proxy target, so update the example file whenever new frontend configuration is introduced.
